# 启动更新提醒

从 Hzip 0.5.1 起，打开主界面约 3 秒后在后台请求公开的 GitHub 最新正式 Release。当前版本来自应用程序集；只有版本号更大才显示提示，不提示旧版、同版、草稿或预发布版本。版本号按数字比较。

弹窗沿用现有对话框样式，显示当前版本、新版本和更新说明，提供“下载新版”“稍后提醒”和“跳过此版本”。下载按钮通过浏览器打开本仓库的安装包地址；缺少有效安装包链接时打开本仓库的发布页。不会执行下载的文件或强制退出程序。

成功检查后 24 小时内不重复检查；选择稍后提醒或关闭弹窗后，最早下次检查再提醒。“跳过此版本”仅屏蔽该版本，更高版本仍会提示。提醒记录单独保存在用户数据目录的 `updates.json`，不会改写已有设置。多个进程共享检查记录。

检查超时为 8 秒，最多读取 1 MiB 响应。断网、超时、GitHub 限流、无效返回或提醒记录不可写时静默结束，不影响压缩解压。主窗口退出时取消检查；主窗口未激活或已有其他子窗口时等待，不抢占密码和解压设置等窗口。右键任务在应用启动的独立分支执行，不检查更新。

`update.json` 的 `updateMode` 设置为 `startup-notify` 时开启，设置为 `manual` 时关闭。API 与可打开的发布和安装包 URL 限定为 `RUI-JACK/Hzip` 的 GitHub 地址。请求只包含常规 HTTP 信息和 Hzip 版本号，不发送文件列表、密码或归档。

0.5.0 没有这部分代码，必须先手动安装 0.5.1 才能使用后续自动提醒。便携用户也可以从发布页下载便携 ZIP 并在退出程序后替换。

## 验证

```powershell
.\tools\dotnet\dotnet.exe run --project tests/updates/Hzip.Update.Tests.csproj -c Release -- verification/update-check
```

19 项检查覆盖数字版本比较、同版/旧版/预发布过滤、限制下载来源、GitHub 真实 API、提醒记录、真实 WPF 弹窗及三个选项、离线、限流、无效响应和取消。新版发布模拟通过测试 HttpMessageHandler 提供固定数据，未在生产程序添加任意更新服务器或假版本开关。应用主界面的 XAML、布局、样式与图标保持不变。
